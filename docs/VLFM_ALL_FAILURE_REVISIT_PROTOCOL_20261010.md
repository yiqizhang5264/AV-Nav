# VLFM 全失败回合：区域回访与低收益折返核查

冻结时间：2026-10-10，全量区域统计之前。此前已查看8例试点，因此这是全量分析前冻结的操作性诊断方案，**不是完全盲态预注册，也不是方法参数校准**。

## 1. 研究问题与范围

要回答“多少失败回合出现低收益的区域折返”，而不是仅找再次选择同一 frontier 的回合。旧区域内相邻、不同甚至新生成的 frontier 也在范围内。几何邻域不是语义房间，不使用测试集真值房间标签指导原策略。

首先完整审计用户指定的 VLFM 原版评估：HM3Dv1 已完成2000回合、失败957；HM3Dv2 已完成1000回合、失败604。MP3D仍在跑，单独冻结已完成快照，绝不写成完整数据集结果。ApexNav未纳入本次可复原日志集合，后续同口径核查不能由VLFM结果代替。

所有完成且 success=0 的回合都留在总分母。按 dataset + scene + Habitat加载后的 episode_id 去重，选最后完整attempt，不按结果挑选。失败终止类型依据最后动作、预算和原控制台分支重建，不能直接使用历史 `failure_cause` 字符串；NF发生在预算边界时优先归NF，防止重复计数。

## 2. 三层验证

1. **全量轨迹筛查**：每个失败回合检查连续步骤、GPS、离开后回到旧位置/区域的轨迹模式。该层只报“空间回返”，不报无效。
2. **全量可复原回合的决策/地图核查**：从已保存RGB-D、传感器和缓存ITM响应在CPU重建原版地图与前沿选择，不重新调用模型，不重新运行导航。每步选中坐标须与历史坐标完全相同，选中分数须匹配原日志显示精度。历史 explore/navigate 模式作为条件输入，不声称独立复原检测器、PointNav或动作。阶梯、缺输入、连接失败、重建不一致者单列未知，不能当阴性。
3. **人工证据复核与后续干预**：每个操作性阳性保留前次访问、返程起点、回到区域、离开/终止四阶段RGB路径、地图及决策记录。自动完成前两层不等于已观看全部视频。人工复核后的结果单独标记；“由该问题造成失败”和“改策略能救回”需真正配对干预，不由回放推断。

## 3. 冻结操作性规则

| 项目 | 主口径 |
|---|---|
| 空间回访 | 与至少20动作以前的已访问位置相距≤0.75m，期间离开该位置≥3.0m |
| 返程起点 | 前次位置到本次回访之间、距前次位置最远的已记录位姿；只作描述性分段，不声称恰是策略切换时刻 |
| 重走通路 | 返程线段按≤0.10m采样，距返程前的轨迹线段≤0.35m的长度比例≥70% |
| 实际返程规模 | 返程位移路径≥2.0m；原地转动不计路程 |
| 抵达后的访问窗口 | 从回到区域到离开3.0m邻域，或原策略因空前沿终止；若预算耗尽仍未关闭，则为右删失 |
| 抵达后的探索被观察到 | 至少一次 explore 模式到达当时所选前沿≤0.75m，或空前沿终止；仅路过走廊不足 |
| 地图收益 | **整个返程＋抵达后访问**的新增 lifetime-union 已探索面积≤0.50m²；不是单看返程段 |
| 语义用途 | 该段有 target_detected 或目标导航则另列，不能视为无语义收益；检测不等于真实目标 |
| 探索用途 | 段内 explore 占比≥80%；混合用途不足则不确认为前沿折返问题 |
| 隔墙保护 | 用最终重建的已知可通行地图，仅作事后排除：两次邻近位姿须在≤1.50m的四连通路径内连通；未知、障碍或跨层不明则待审 |

重复路径可以同向或反向，指低收益的重复运输而非限定180度反向。不同 frontier 的坐标差仅为辅助诊断，不是必要判据。最终地图是**事后诊断工具**，不能当作当时规划器已有信息。无阶梯报告也不等于具有完整3D楼层证明，此限制须披露。

只有一个前沿/可能只有唯一出口的回撤，独立标注“可能必要”，不能据此认定选点错误。即使存在其他前沿，也仅证明有候选，不证明替代路线可达或能成功。

低收益事件取并集统计动作与路程，不重复累加嵌套事件。同一连续区域访问只记一次；该保守分段可能漏掉大房间内部更细的往返，不能把未命中写成绝对不存在。

## 4. 统计与不确定性

每个数据集报告：全部失败数、完整可复原数、无法判断数、空间回返数、高重复通路数、操作性低收益回访数、可能必要回撤数、人工确认数；同时按终止类型、场景、目标类别拆分。所有百分比分母显式写出；人工未审不得冒充已确认。

主口径不随结果修改；完整给出新增面积阈值0/0.1/0.5/1.0m²与路径重复比例0.5/0.7/0.9的敏感性，不能从中挑最有利组合。地图收益是原策略处理后的二维已探索面积，不等于真实可见信息、更不等于语义信息增益。

保留已有成功试点作为“必要回撤/有收益回访”反例。未做全成功对照前，不声称该现象在失败中比成功中更常见，也不从失败条件样本推断总体发生率。

## 5. 实施与安全

- 原始评估和服务只读，不修改VLFM源码、评分、地图融合、循环抑制或其他用户GPU任务。
- 固定commit独立worktree；所有代码、源文件、manifest与协议哈希随产出记录。
- `screen_allfail_routes.py`检查全部失败；`run_allfail_frontier_audit.py`逐回合CPU重建、核验和分析，单个失败不中断后续，也不静默略过。
- 默认一个低优先级worker，OpenCV/BLAS各1线程，CUDA不可见；最多两个worker。结合当前服务器繁忙程度默认使用1个，不启动视觉服务。
- 本次不保存全量逐步大地图，仅保存紧凑决策日志和最终连通性审计掩膜；原RGB/深度保留引用，不复制大量原始数据。
- 可断点续行，但 manifest、代码和协议哈希必须全部一致；不得把不同口径混入同一结果目录。
- 完成后产出逐回合JSON台账、逐回访区间及证据索引、汇总Markdown。严格因果数量待后续真实干预另报。
