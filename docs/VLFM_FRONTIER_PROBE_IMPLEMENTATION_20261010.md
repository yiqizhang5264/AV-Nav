# VLFM 重复折返：决策证据与分层验证实施方案

日期：2026-10-10。此方案是问题诊断，不是已验证有效的新导航方法。

首批实施和服务器结果见 `VLFM_FRONTIER_PROBE_RESULTS_20261010.md`：8 回合、2,761 次前沿选择全部复现；未执行 C 层反事实闭环。

## 1. 要回答什么

已有数据可定位实际目标点、机器人位置、候选前沿和探索/目标导航模式；部分控制台还记录保持旧前沿、循环抑制和无前沿停止。缺失的是**全部前沿的准确评分、被比较/未比较的分支、上一状态和实际循环判定**，因此无法仅由位置唯一反推选择理由。不应说成完全不知道机器人为何选点。

本轮先不改变 VLFM 行为。原始基线固定为 `external/vlfm@584ed56008754fde7997d904983607def8328322`，证据采集包装器基于 `5596d7a`。本地隔离工作树开发，经 origin 同步到服务器新工作树；不改运行中的 MP3D 工作树，不重启其服务，不占用 GPU 做首轮验证。

## 2. 三个层次与证据边界

### A：是否存在重复折返（轨迹事实）

先在全部已完成回合中筛查，失败优先检查、成功作为对照。记录离开已访问区域、转向旧区域、重走边和再次离开的区间；区分探索导航与目标导航、碰撞原地摆动、楼层转换。首轮保持既有筛查定义：曾离开至少 3 m、至少间隔 20 个动作后回到 0.5 m 内。它是候选筛查规则，不等于同一条边重复，也不等于无效探索。

报告：回返回合数、次数、回返路程/动作、重复边比例（后续有实际三维位姿时分层构图）、失败类别以及成功对照。不能把 A 层命中数称为“因重复探索导致失败数”。

### B：是否由低收益旧前沿选择造成（决策与收益证据）

将 A 的区间连接到逐步前沿决策：当时走的是目标导航还是前沿探索？旧前沿为何保留/重选？是否有更近的候选？返程后新增了多少已探索空间、是否看到了新目标证据、前沿消失/分裂/重新生成？

收益采用机器人在线构建的地图，记录原始 explored、navigable、obstacle、value/confidence；地图的 explored 可因轮廓处理减少，所以同时记录历史并集 `ever_explored` 和每步移除量，不能直接把当前总面积之差当信息增益。`ever_explored` 仍是处理后的地图代理，不宣称等于真实可见区域。原始 RGB-D 与检测结果用于人工核验。

前沿身份关联是离线诊断元数据，不影响规划：连续帧邻近匹配、门限/歧义/分裂合并都需记录；没有足够证据时标记关联不确定，不硬认定同一前沿。历史初筛的 0.5 m 回返阈值与 VLFM 本身 0.5 m 的旧前沿匹配阈值应分别注明，二者用途不同。

首批固定 8 例：每个 HM3D 版本各 1 个 step-budget failure+折返、1 个严格 no-frontier failure+折返、1 个 success+折返、1 个未命中折返的 budget failure。优先探索模式案例，尽量跨场景。选择发生在新诊断结果之前，属于目的性机制样本，不能估计总体干预收益。

### C：减少这种选择是否真的能救回（配对因果验证）

只有 A/B 证据闭合后才定义一个单一干预，例如对已访问且低新增收益的前沿增加可解释的回返成本，并保留“无新候选时可回退”通道，避免制造新的 no-frontier。形式示例 `U(f)=V(f)-lambda*D_return(f)*(1-G_new(f))` **仅是待审方案，不是本轮已冻结/已实现算法**；不同量必须先统一尺度。系数/预算只能在 train/development 选定，不能按当前 val 失败救回多少反调。

固定参数后，同 episode 身份/起姿/种子分别运行原始 VLFM 与单一干预；保留成功对照，量化救回和新损失。报告 SR、SPL、总路程、stepout、no-frontier、碰撞、返程成本和新增地图收益；按场景汇总/重采样。必须报告首个行为分歧点，之后不能拿原轨迹继续离线推算新策略的最终结果。视觉缓存重放只验证原轨迹决策，不证明反事实成功。

## 3. 必须补采的数据

| 层 | 必需字段 | 用途 |
|---|---|---|
| 身份 | 原 shard SHA256、加载后的 episode_id、scene、target、起始位置/朝向、配置和代码哈希 | 避免单独筛 JSON 后被 Habitat 重编号 |
| 时序 | pre-action step、动作、post-action reward/done、mode、终止分支、单调时钟 | 区分探索、目标导航和终止原因 |
| 位姿 | agent/camera XYZ 与 quaternion、episodic XY、地图原点/分辨率/epoch | 排除跨楼层二维重叠、对齐轨迹和地图 |
| 前沿 | 原始输入顺序、坐标、排序后坐标、target/exploration 原分数与实际归约通道 | 复现排序而非根据彩色地图猜分 |
| 选择 | 上次 frontier/value、0.5m 匹配、+0.01 保持条件、每次真实 cyclic 检查、未检查原因、实际选中索引和分支 | 解释为何选它、为何跳过其他点 |
| 地图 | 原始 obstacle/navigable/explored、ever_explored、value/confidence 的无损增量 | 定量计算回返后的可观测收益 |
| 视觉 | 已有 RGB、depth、ITM 请求/响应、检测与 mask 文件引用，服务错误/耗时 | 判断是否视觉价值吸引、是否真有新目标证据 |
| 路径 | 实际动作/轨迹、可达性与回访区间 | 直线距离不冒充实际路径成本 |

所有 GT/仿真真值只用于事后诊断，不输入导航决策。若原始日志缺高度，只可报告二维同楼层代理，不能补造三维位姿。

## 4. 实施代码与隔离

- `scripts/decision_trace.py`：在原始选择函数内部做只读挂钩，不额外调用打分或 `check_cyclic`，不改变排序、状态更新次数和返回值；原源码哈希不匹配则停止安装。
- `scripts/replay_frontier_probe.py`：使用原有 depth/sensors 与缓存 ITM 分数，在 CPU 重建原图和选择状态。每步和历史 nav_goal/前沿核对，出现不能解释的差异则该例不得进入正式 B 层结论。清楚区分重放字段与原始记录。
- `scripts/frontier_probe_recorder.py`：新在线实验的完整 XYZ 审计与地图无损增量、逐决策 JSONL；不读取 GT 来改变行为。
- `scripts/run_vlfm_frontier_probe.py`：独立入口，在临时源码 overlay 中安装旁路日志；原 pinned submodule 不改。按完整 shard 加载后筛 episode，核对目标/起姿，不裁剪原 episodes 列表。
- `scripts/select_probe_episodes.py` 与固定 manifest：失败优先且包含反例/成功对照；不按新结果更换样本。

在线入口使用 `--probe-case`（单个含完整 `identity` 的 JSON）、原有 `--vlfm-root` 和 Habitat 配置；`VLFM_EVIDENCE_DIR` 必须是不存在的新目录。单例 `test_episode_count=1`，保持原 500 步上限。GPU 在线复跑使用独立工作树、端口和服务资源；本轮 CPU 诊断不联系正在跑 MP3D 的服务。

## 5. 验收与不确定性

1. 合成单测覆盖保持旧点、同分、循环跳过、全部 cyclic 回退、空前沿；instrumentation 开关前后返回与状态一致，不能只看最终 success。
2. 地图增量重建逐字节一致，包括 signed zero/NaN；episode 身份不一致立即停。
3. 历史重放逐步验证，不足字段和不匹配例子单独报告，禁止静默跳过。
4. 运行中 MP3D 与 GPU 服务保持不动。原始基线问题仅审计，不悄悄修复。
5. 三层分别报告“轨迹折返”“低收益决策证据”“配对干预收益”；不跨层替代结论。

## 6. 源码核对发现（待实验验证，不修改基线）

原始选择器优先保留当前值下降不超过约 0.01 的旧前沿，再按分数顺序做循环检查。全被抑制的分支注释称 closest，但实际 `max` 原始 frontier 距离所得索引用于排序后数组；记录实际行为，不把注释当真。`StateAction` 的哈希/相等比较也需测试其集合查询是否真正匹配历史记录。发现这些问题不等于它们造成了某一回合失败：需看实际触发与配对干预。
