# OCS train-5：身份记录修复与原版结果复核

日期：2026-11-02。

## 修复结论

原版 VLFM 的五条回合确实已执行完毕。此前失败的是回合身份记录和运行后的核验，不是五条仿真都没有跑完。原始结果保留，独立复核通过，不改写历史观测文件。

根因：Habitat 的 `VectorEnv.current_episodes()` 默认返回简化的 `BaseEpisode`，只有场景与加载后的回合 ID；目标类别、起始位置与旋转不在其中。旧记录器将缺失字段写为 `unknown/null`，核验器随后对 `None` 调用 `tuple()` 而崩溃。

修复提交 `5397109`：

- 每次新回合通过 `call_at(index, "current_episode", {"all_info": True})` 读取实际环境中的完整任务对象，并检查其场景和 ID 与当前回合一致。
- 每个回合缓存一次，只读 RPC 不执行 `step` 或 `reset`，不从预期任务表拼装“观测到的身份”。
- 记录前拒绝缺失类别、非法位置或旋转，防止再次静默写入空身份。
- 子进程返回后先写 `worker_exit.json`；身份核验异常也会生成明确失败的 `completion.json`，不再丢失退出状态。

提交 `11296ba` 同步修正前沿深核查工具的日志注入钩子，保持采集顺序为“完整任务读取 → 当前观测记录 → 环境诊断记录 → 策略与环境执行”。

服务器真实依赖环境的全套测试：**198/198 通过，无跳过**。测试覆盖真实 Habitat `all_info` API（不启动模拟器）、读取缓存、非法身份拒绝、原始记录不改写、位姿或目标不匹配拒绝、缺失终态拒绝，以及前沿工具注入兼容性。
