# AV Nav 主动视觉验证实验实施方案

本方案以 VLFM 为第一阶段研究平台，在相同感知模型和确认规则下，比较被动观测、随机视点与成本感知主动视点的作用。待 VLFM 上的有效性成立，再接入 DSVR-Nav，验证主动证据获取与第三章可靠语义确认机制的互补性。第一版为工程及方法假设验证，不预设任何成功率提升。

实施目录为 D:/zyq/AV_nav，服务器工作目录为 /home/zyq/AV-Nav，代码经 GitHub 仓库 yiqizhang5264/AV-Nav 同步。服务器使用 SSH 端口 50001。认证依赖已有 SSH 密钥或本地 Git 凭据管理器；密码、令牌和私钥不进入仓库。

## 1 研究问题与阶段出口

核心问题是：当目标候选的当前观测不足以支持可靠确认时，机器人能否通过有限代价的视点移动获得更有效的视觉证据，并改善最终目标导航表现。

H1 主动选择视点在匹配验证图像数量和动作预算后，优于原地观察和随机可达视点。H2 尺度自适应观察范围相对固定范围能够改善小目标或边界裁剪条件下的有效观测。H3 在完整 DSVR-Nav 中，主动采样能够恢复部分证据不足的真实候选，同时控制错误停止及附加路径。

阶段 A 跑通固定版本 VLFM、服务器模型服务、数据路径和逐回合日志。完成训练集小样本冒烟测试，确认无导入错误、无丢失结果、无跨回合状态污染。该阶段不解释 SR 高低。

阶段 B 使用训练场景建立校准集和开发集。固定验证器与候选入口，完成 single、passive、random、nearest、fixed_radius、active 对照。先分析触发覆盖率、候选匹配和新观测质量，再检查完整导航收益。

阶段 C 冻结方法参数与数据清单，在独立验证场景上进行配对评估。若只改善局部分类而未改善导航，应分析额外动作、触发时机及目标丢失，不直接宣称方法有效。

阶段 D 将主动采样接口接入 CMVC 候选池，新鲜观测回灌 CMVC，保留 NFRR。以完整 DSVR-Nav 和 DSVR-Nav+AV 为主要对照；加入提前回访和放宽确认阈值对照，区分收益来源。

## 2 固定平台与复现边界

VLFM 上游固定为 bdaiinstitute/vlfm 提交 584ed56008754fde7997d904983607def8328322，通过 Git 子模块记录。AV-Nav 不直接修改上游算法源码，通过独立策略类和运行入口接入。服务器已有 /home/zyq/vlfm 包含个人修改，首轮不将这些修改混入官方基线。

服务器已有环境为 /home/zyq/miniconda3/envs/vlfm，Python 3.9、PyTorch 1.12.1+cu113、NumPy 1.26.4、Habitat-Sim 0.2.4、Habitat-Lab 与 Habitat-Baselines 0.2.4。每次实验保存 pip freeze、AV-Nav 提交、上游提交、工作区状态、完整命令、配置、数据清单哈希与退出码。

当前服务器数据位于 /home/zyq/vlfm/data。新目录链接既有数据、权重、YOLOv7 与 GroundingDINO 资源，避免重复下载。正式报告必须同时记录 episode 数据版本、场景资源版本和传感器设置，不能仅凭目录名 v1 推断 HM3D 场景版本。

模型服务使用独立端口 13181 至 13184，分别运行 GroundingDINO、BLIP2 图文匹配、MobileSAM 和 YOLOv7。既有 CUDA 11.3 与 RTX Ada 的 DINO NVRTC 运算不兼容，因此 DINO 默认使用 CPU，其余模型与导航使用 GPU 3。所有对照共享该设置；启动前检查显存及既有作业。服务只监听本机，使用已有离线权重，不升级原 conda 环境。

## 3 第一版实现与后续研究范围

原始 baseline 使用未更改的 HabitatITMPolicyV2。其候选入口已经经过检测置信度与目标点云规则过滤。因此第一版结论仅覆盖 VLFM 已接纳的候选，不声称恢复所有弱检测或从未检测到的目标。

所有验证组使用同一观测抽取方法和同一冻结确认器。通过检测框的 SAM 掩膜与有效深度建立局部可见点云，以三维中心距离近似关联当前导航候选。该关联是 MVP 实现，尚不是稳定实例跟踪；相邻同类目标、大型物体或点云漂移必须记录并单独审计。

RGB-D 坐标使用 VLFM 约定：相机 x 向前、y 向左、z 向上。归一化深度先按最小和最大量程恢复为米；排除零值、无效值和接近最大量程的点，再以分位数截断减少背景深度污染。

当前确认器对无标注候选裁剪计算 BLIP2 ITC 正负文本余弦差，负文本词表在配置中固定，并排除当前目标类别。该差值是启发式语义间隔，不是目标概率，也不是原论文 CMVC 的复现。各验证组共享此确认器，后续可替换为统一 VQA 验证器，但必须重新运行所有对照。

根据掩膜占比、边界接触率与有效深度比例计算观测质量。高质量且语义间隔高于上阈值的候选可继续目标导航；高质量且低于下阈值的候选暂时拒绝；其余候选进入主动验证。执行 STOP 仍需原始目标到达条件；验证视点到达不等于任务成功。

初始参数 low=-0.03、high=0.03、质量阈值 0.35、目标掩膜占比 0.08 均为开发初值，不是已校准结论。训练集校准后建立新配置文件，冻结后禁止根据最终评测结果调整。

## 4 观察位置与预算

可靠观测下采用 d*=clip(d×sqrt(area/target_area),1.0,2.5) 米近似确定目标表面观察距离。面积与距离平方反比只适用于可见面积变化较小的近似条件；当裁剪明显或深度可靠性不足时退化为固定距离 1.5 米。遮挡造成的小掩膜仍可能误导距离估计，应在消融和失败案例中说明。

使用 8 个方位和 0.8、1.0、1.2 倍观察距离生成最多 24 个候选视点。表面修正由当前可见点云在对应方向的鲁棒投影估计，不代表完整物体表面重建。固定半径对照关闭自适应距离；表面修正应进一步单独消融。

候选必须位于已观察的自由空间，使用包含机器人半径膨胀的障碍图。通过有预算上限的网格最短路径搜索验证可达性，禁止对角线穿过障碍拐角。搜索仅使用在线地图，不读取 Habitat 真值 navmesh。

通过二维视线近似过滤完全被障碍遮挡的视点，并排除目标自身的局部表面区域。二维可见性不等价于真实三维可见性，靠墙、大型家具和低矮遮挡应单独核查。

效用由相对历史观测方向的互补度、预测视觉尺度与真实网格路径代价构成。该函数称为观测效用，不称为严格信息增益。random 在同一可行集合内随机选择，nearest 选择路径代价最小点，active 选择效用最大点。

第一版每次候选验证最多 2 轮，总移动路径预算 3 米，总动作预算 24 步，整回合验证动作预算 64 步；预算覆盖移动、转向和扫描。初值需要根据训练集触发成本校准。记录计划路径与实际路径，不能用两者差值直接充当相对基线的因果额外路径。

到点后先朝向目标，再使用适配 Habitat 30 度离散动作的 0、-30、+30 度扫描。原方案 ±15 度不能直接用于默认 30 度动作空间。passive 组在原位置执行有界转向取样，称为原地观察对照；由于环境没有 WAIT 动作，不将它描述为传感器完全静止的多帧采样。

## 5 证据融合与回退

每轮扫描仅选取质量最高的候选匹配观测进行确认，新旧视角采用共同质量加权语义间隔。无有效匹配观测只记为缺失，不能单凭一次检测失败拒绝目标。无法生成可达视点、预算耗尽或持续不确定时，暂时抑制该候选并恢复原探索。

同一候选的临时抑制默认持续 30 步，避免无限重复验证。已确认缓存、实例匹配和跨回合重置需要在集成测试中检查。实际验证到达位置不直接触发 STOP；最终仍回到原始候选导航目标。

第一版不实现完整三维补全、学习式 NBV、端到端策略训练、精确遮挡恢复概率或未经校准的贝叶斯对数赔率累积。若以后实现，作为新的实验版本，并保留当前版本作为对照。

## 6 数据划分与实验矩阵

smoke5 从训练 split 确定性抽取 5 个回合，尽量均衡类别，步数限制 100，仅检查环境与数据链路。随后 smoke20 使用完整任务步数检查候选触发、动作与日志。

正式开发从训练场景按场景划分 Calibration-300 与 Dev-100。make_split 使用固定场景哈希将训练场景划为约 75% 校准场景与 25% 开发场景，再按类别确定性抽样。分别使用 --partition calibration 与 --partition development，生成后核查场景交集为空。初始 smoke5 已冻结，不因抽样工具更新而重建。

最终评估使用预先固定的验证场景全量回合或与第三章一致的公开清单，不参与阈值、负提示、方法与困难子集规则调整。导航 seeds 建议为 17、29、43；随机视点至少报告多种随机种子，以判断随机策略波动。

B0 原始 VLFM。B1 VLFM+single，加入共同确认器。B2 VLFM+passive，原地观察。B3 VLFM+random，随机可达视点。B4 VLFM+nearest，最近可达视点。B5 VLFM+fixed_radius，固定观察距离与相同效用。B6 VLFM+active，完整第一版方法。A1 去除视角互补项。后续加入表面修正、多环与触发策略消融。

B1 至 B6 固定检测器、候选入口、确认器、语义阈值与质量阈值。B2 至 B6 匹配每轮送入确认器的图像数与最大动作预算，同时报告实际消耗。原始 B0 不额外调用确认器，B0 到 B1 的收益不能归因于主动视点。

困难子集根据基线观测预先定义小掩膜、边界裁剪、远距离、深度不足和语义冲突。子集仅用于分层分析，不能只挑选 AV 成功的回合，也不能因方法改变观测后重新定义有利子集。

## 7 指标与结果判定

主指标为官方 SR、SPL 和逐回合 distance_to_goal。成本指标为验证触发次数、验证动作数、验证阶段实际路径、额外确认器调用数和运行耗时。区分附加确认器调用与包含探索在内的模型总调用。

错误停止需区分语义假阳性、正确类别但未满足到达条件、无前沿 STOP 与超时。当前 summarize 工具输出 unsuccessful_target_stops，明确它比语义 False Stop 更宽泛；不能把该数值直接写成语义假阳性率。

若报告 FSR，应同时报告 FalseStops/AllStops、FalseStops/AllEpisodes 和原始计数。Verification Accuracy 必须依赖独立候选标签；不能用模型自身答案作为真值。Uncertainty Reduction 在未校准概率时不作为主结论，仅报告语义间隔和观测质量变化。

完整导航比较必须使用 scene_id+episode_id 配对，报告 baseline失败→AV成功、baseline成功→AV失败和净变化。汇总程序拒绝缺失回合或不一致回合集的配对。当前提供 episode bootstrap 区间；正式论文建议增加场景聚类 bootstrap，考虑场景内相关性。

进入 DSVR-Nav 集成的条件为：方法正确执行；主动策略优于强对照的趋势在开发集和多个 seeds 下稳定；收益可以通过证据质量与失败转移解释；完整导航代价可接受。无需硬性预设 SR 提高多少个百分点，更不能以小样本偶然增益作为结论。

## 8 本地开发与服务器运行

本地仅安装轻量 Python 和 NumPy，用于配置、几何规划、日志分析及回归测试。执行 python -m unittest discover -s tests -v。Habitat、GPU 推理与全量数据运行在服务器现有环境中，避免在 Windows 本地构建 Habitat。

本地修改后先 git status，显式 git add 所需源文件，再 git commit 与 git push。服务器在 AV-Nav 目录执行 git pull --ff-only 和 git submodule update --init --recursive。启动一个固定 run-id 的实验，运行中不对其代码目录执行更新；长实验应使用独立 Git worktree 固定提交。

服务器产生可分享的结果摘要后，把小型指标与环境摘要写入 results，再显式提交并推送到 GitHub。本地 git pull --ff-only 拉回。原始 runs、模型、场景、视频及认证文件均忽略，原始产物需要时通过 scp 下载。

scripts/sync.py 提供 status、pull、push。若工作区存在修改则拒绝同步，不自动 stash、不覆盖、不强推。两端不要同时修改同一分支；先推送当前工作，再由另一端拉取。发生分叉时先保存两端提交，在本地审查合并。

每个 run-id 唯一，已有目录不覆盖。manifest.json 记录配置与提交，console.log 记录运行日志，episodes.jsonl 保存每个完成回合的官方指标，verification.jsonl 保存主动验证事件，environment.txt 保存依赖，exit.json 标记返回码。没有 exit.json 时不能视为完成；有非零返回码时不能当作有效实验。

## 9 三个月执行安排

第 1 至 2 周：服务器基线、数据和模型资源核查；完成 smoke5、smoke20 与候选日志审计；建立互斥 Calibration-300 和 Dev-100。若核心环境未跑通，暂停方法扩张。

第 3 至 4 周：校准共同确认器，验证候选关联与抑制回退；跑 B0、B1、B2、B3。重点确认是否存在可恢复的目标确认错误及其数量。

第 5 至 6 周：验证自适应距离和视点效用；跑 B4、B5、B6 与关键消融。审计无可达视点、目标丢失、实例错配和动作预算。

第 7 至 8 周：冻结参数和协议，运行独立评估、多 seeds、困难条件和配对失败分析。若只有更多确认器调用带来收益，应调整论证或方法，而不是隐藏对照。

第 9 至 10 周：对接 DSVR-Nav 的 CMVC 候选状态、观测输入和 NFRR 调度。AV 只负责补充观测，不重复宣称 CMVC 融合为第四章创新。

第 11 至 12 周：完成 DSVR-Nav 集成对照、总体结果与失败案例，整理方法和实验章节。VLFM 上的方法验证与 DSVR-Nav 上的互补性验证分别陈述，不保证两者具有相同增益。
